## 已完成的生产化改造

1. 真实保证金支付单
   - 一个用户在一个专场只保留一笔保证金记录。
   - 支付宝 H5/App 和微信 JSAPI/App 均创建真实支付参数。
   - 只有支付平台验签通过且金额完全一致，保证金才变为已支付。
   - 支付状态查询支持支付跳转后的结果确认。

2. 并发与幂等出价
   - 出价事务先对拍品行执行 `SELECT ... FOR UPDATE`。
   - 校验专场保证金、拍卖时间、最低价格和加价幅度。
   - `user_id + request_id` 唯一约束阻止网络重试造成重复出价。
   - 最高出价、拍品价格、买家和出价次数在同一事务更新。

3. 截拍与保证金处理
   - 定时完成到期专场，按保留价判定成交或流拍。
   - 中标用户保证金进入抵扣状态；未中标保证金调用原支付渠道退款。
   - 退款号固定且失败保留待重试，避免重复退款。

4. 安全与运行配置
   - 外部传入的 `X-User-Id` 被清除，只接受验签 JWT 生成的内部身份。
   - 管理写接口默认关闭，必须配置独立管理密钥。
   - 数据库、Redis、支付、日志、回调地址均改为环境变量。
   - 生产环境关闭演示数据写入。

5. 实时竞价与入口
   - 前后端统一为原生 WebSocket `/ws/auction/lot/{lotId}`。
   - Nginx 已配置 `/api/auction/` 与 `/ws/auction/` 代理。
   - 拍卖已成为主包页面和正式底部导航入口。

## 上线首场前必须执行

1. 在管理侧配置真实专场、拍品、起拍价、加价幅度、保证金、保留价和起止时间。
2. 使用受控买家账号完成一笔小额保证金支付，并从支付商户后台核对回调金额和订单号。
3. 两个测试账号同时出价，核对只产生一个最高价且重复 requestId 不重复落单。
4. 结束测试拍品，核对成交/流拍状态及未中标保证金原路退款。
5. 对中标后的尾款订单/线下交割流程做业务确认；当前服务负责竞价、截拍和保证金处理，不替代订单域的尾款履约流程。

## 自动化说明

应用内浏览器控制初始化仍报 `Cannot redefine property: process`，所以没有自动点击 UI；公网 API、WebSocket、静态资源、容器和日志验收不受该工具问题影响。
